Implemented
- Independent area and module Anomalie, existing department/module catalog integration.
- Central extensible agent registry, severity/category/owner/status/deadline, evidence,
  comments, immutable event audit, optimistic versions, deduplication per agent/fingerprint.
- Source module authorization, explicit area AND module checks, owner/department scope,
  RLS on all new tables; no user/role/department grants are assigned by the migration.
- Manual BRAIN_REVIEW through the existing brain proposal channel for management,
  task links and recipient configuration. No order/planning execution is added.
- Existing task links validate current task scope and activity module authorization.
- Dashboard and paginated register/history, direct Workspace record links.
- ChatGPT tools ANOMALIES_READ, ANOMALY_HISTORY, ANOMALY_AGENT_STATUS,
  ANOMALY_UPDATE, ANOMALY_CONFIGURE, without model API calls.
- Deterministic 28-day rules for BOM, materials, external commitments, purchase
  requirements/orders/dates, yesterday receipts/quality, capacity and dependency cascades.
- Physical stock/movement reconciliation requires verified warehouse/article/UM/lot,
  semantics, event identity, signed quantities and synchronization coverage. Accounting
  differences and available-vs-physical differences are never classified as stock errors.
- DST-aware 07:00 Europe/Rome scheduler, atomic daily run ingestion, no uncertain retries.
- Dynamic recipient resolver: department members' unique existing responsible person,
  both active Workspace administrators (live audit count: 2), configurable department
  overrides and additional users; deduplicated email addresses. Ambiguity blocks delivery.
- Dedicated planning read gate for authorized company-wide scopes, independent of write.
  Restricted scopes fail closed until MES supplies an authoritative row mapping.
- MES companion change adds lot, Mexal lot ID, UM, physical basis, source timezone and
  read timestamp to inventory. It deliberately does not invent a synchronization watermark.

Not implemented or not activated
- Production loadSnapshot adapter normalizing all nine input sources is NOT installed.
  The scheduler has no default source loader and cannot execute a real daily analysis.
- PDF generation from the exact Word master, field/TOC refresh, rendering QA and
  recipient-specific PDF delivery are NOT wired. No generic PDF substitutes the master.
- anomaly_deliveries is a protected deduplication ledger only; no delivery dispatcher
  or notification queue producer is connected. No email or notification has been sent.
- The MES companion change requires its own reviewed release/install and live read test.
- Source synchronization watermarks and canonical cross-system movement mappings
  remain unavailable; data update timestamps cannot substitute for them.
- Agent enabled=false, readiness.ready=false. Manual activation is rejected while false.
- No management order, material reservation, lot, production or planning change was
  applied during testing. All tests use isolated data and mocked transports.

Release gates before activation
1. Install/test the MES read contract and all normalized read-only source adapters.
2. Verify authoritative snapshots, physical/available semantics, movement mappings,
   synchronization cutoffs, department mappings and source permissions.
3. Install deterministic Progre Word-to-PDF rendering with field refresh and full QA.
4. Integrate individual scoped report/email and notification delivery with the existing
   transport, leases and accepted/delivered/uncertain statuses; no uncertain resend.
5. Verify each dynamic recipient's active identity, source permissions and report scope.
6. Test the complete flow with non-delivering fixtures, then present a specific activation
   proposal for manual BRAIN_REVIEW in Workspace. Do not set readiness to true merely
   because a code build, role check, migration or cron deployment succeeded.
